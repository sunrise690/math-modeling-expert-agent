## 1. 适用范围与证据边界

本契约用于把已完成的建模、计算和验证组织成可复跑、可审计、可答辩的 CUMCM 论文包。它约束产物，不提供历年答案，也不以模型数量、算法新颖名目或篇幅替代证据。

本契约依据本地论文审读形成。样本身份必须按以下边界陈述：

- A127、C050、A242 已由组委会论文展示、作者信息和官方获奖名单交叉核验为本科组全国一等奖；其中 A127 获知网研学奖，A242 获北太天元数模之星。
- A147、A001、B334、D001、E176 只能称为“组委会官方展示论文”；现有公开证据不足以把匿名论文代码逐篇匹配到全国一等奖队伍。
- A175 只能称为“本地方法与缺陷样本”；未核验其官方展示或奖项身份。
- 论文被展示、发表或获奖不证明其中每个公式、数值和结论都正确。必须吸收其结构优势，同时独立复算并修复已发现的缺陷。

不得把本契约描述为“获一等奖公式”，不得承诺、暗示或预测必然获奖。最终表述只能是“达到本契约的内部高水平交付标准”；实际奖项由当年题目、完成度、评审和竞赛规则共同决定。

## 2. 交付状态与目录契约

完整论文包至少包含以下逻辑目录；宿主系统可改变文件格式，但不得省略语义：

```text
paper-package/
├─ 00_provenance/          # 题面、附件、资料来源、哈希、版本、证据边界
├─ 01_prewrite/            # 四类写前工件
├─ 02_src/                 # 唯一入口脚本、模型、求解、验证、绘图代码
├─ 03_runs/                # 环境、参数、种子、求解器状态、日志
├─ 04_results/             # 未取整原值、展示值、约束复算与结果清单
├─ 05_figures/             # PNG/PDF/SVG、绘图数据、图清单
├─ 06_validation/          # 分问题验证包、独立实现、审计状态
├─ 07_references/          # BibTeX/引文表、来源快照与引用核验
├─ 08_paper/               # 正文源文件、最终 PDF、AI 使用说明
└─ manifest.json           # 本次交付的文件、哈希、生成关系与状态
```

同一论文包只允许一个“最终运行”。摘要、正文、表格和图必须引用该运行的 `run_id`。探索运行可以保留，但不得与最终运行的数字混写。

## 3. 动笔前必须完成的四类工件

四类工件全部完成前，不得撰写正式摘要，不得用占位数字填正文。

### 3.1 工件 A：来源与输入证据账本

固定字段：

- 题面、附件、补充说明、外部数据和参考资料的文件名、版本、获取时间、哈希。
- 每个数据字段的定义、单位、时间/空间范围、缺失、重复、异常编码和变换规则。
- 每条外部事实的来源级别：官方题面/原始数据、标准/教材/同行评议论文、权威机构网页、二手资料、Agent 推断。
- 奖项、作者、论文身份的证据边界；无法交叉核验时标记 `unverified`，禁止补全。
- 数据许可、引用要求和不能公开的内容。

验收：任一输入都能定位来源和版本；任一推断都不会伪装成题面事实。

### 3.2 工件 B：逐问交付与依赖矩阵

每一问一行，固定字段：题目动词、输入、输出、单位、精度、必填表/图/附件、上一问接口、下一问接口、验收指标、失败回退路线。

额外生成模型链图，明确：

- 哪些模型跨问复用。
- 哪些变量在后一问被放宽或新增。
- 哪些结果是优化器输入、约束、参数或验证基准。
- 若后一问另起模型，说明前一问为何不可复用。

验收：题面中的每个动词、表格字段和精度要求都映射到具体产物；嵌套可行域关系已标注。

### 3.3 工件 C：模型—求解—验证卡

每个核心模型一张卡，固定字段：

- 现实实体、状态、决策、观测、参数、随机量及单位。
- 坐标系、时间原点、方向、采样频率、初边值条件。
- 方程、目标、逐条约束、容差、守恒量/不变量和适用域。
- 主路线、保底基线、独立验证路线及路线淘汰理由。
- 求解器、版本、初值、终止条件、失败重试、随机源。
- 主张类型及对应验证：收敛、预测外推、可行性、统计推断、物理一致性、鲁棒性或最优性边界。

验收：量纲一致；存在可运行基线；核心结论至少预注册一项独立于主求解器的验证。

### 3.4 工件 D：主张—表—图—引用蓝图

每条计划写入摘要或结论的主张一行，固定字段：

- 主张文本和状态：`exact`、`bounded`、`heuristic`、`provisional`。
- 产生该主张的脚本、结果表字段、图号/表号和 `run_id`。
- 数值、单位、有效数字、误差/区间、基线和适用条件。
- 独立验证证据及审计门。
- 所需外部引用；引用支持的是背景、方法来源、参数还是对比数据。

同时生成论文骨架和图表清单。无证据链的主张不得预留在摘要；没有明确主张的图不得进入图表清单。

验收：摘要候选数字能追到原始结果，外部事实能追到引文，所有图表都有“要证明什么”。

## 4. 论文生产顺序与篇幅预算

严格按以下顺序生产：结果表与验证报告 → 正文逐问章节 → 模型评价与局限 → 结论 → 摘要 → 参考文献核验 → 全文一致性审计 → PDF 视觉检查。禁止先写摘要再倒推结果。

在当年官方格式没有更严格限制时，建议正文形成 18–28 页的紧凑稿；封面、承诺页、目录、参考文献和附录是否计入，以当年规则为准。页数是容量建议，不是评分项。

建议预算：

| 部分 | 建议占比 | 必须承载的内容 |
|---|---:|---|
| 摘要与关键词 | 3%–5% | 逐问方法、量化结果、关键验证和结论边界 |
| 问题重述、分析与模型链 | 8%–12% | 任务接口、依赖关系、路线选择 |
| 假设、符号与数据处理 | 8%–12% | 可检验假设、单位、数据质量和防泄漏 |
| 各问模型、求解与结果 | 50%–60% | 逐问微结构、核心公式、结果与解释 |
| 检验、敏感性与鲁棒性 | 12%–18% | 与主张匹配的独立证据 |
| 评价、推广与局限 | 5%–8% | 适用域、失效边界、近似和改进 |
| 结论与引用 | 5%–8% | 逐问结论、引用闭环 |

禁止为达到 18 页灌水。以下内容应删除或移入附录：教材式算法介绍、与本文无关的历史背景、重复题面、大段代码、可由表直接读出的逐项复述、无主张装饰图、未被使用的模型。若完整证据在 18 页内已清楚表达，应保持更短；若超过 28 页，应先压缩重复解释和合并同类证据，不能删除关键验证来凑页数。

## 5. 逐问正文微结构

每一问必须形成可独立审阅的小闭环，按以下顺序书写；相邻小节可合并标题，但内容不得缺项。

### 5.1 任务与接口

用 2–4 句说明本问要计算/判断/设计什么，输入来自哪里，输出进入哪张表或下一问。列出精度、单位和边界条件，避免重复整段题面。

### 5.2 现实语义与假设

说明实体、机制和可忽略因素。每条关键假设必须标记来源、可检验方式和可能影响；不得使用“误差可忽略”“过程稳定”等无量化假设掩盖困难。

### 5.3 模型建立

先定义符号和单位，再从守恒、几何、统计生成机制或业务关系推导方程。优化问题必须显式给出决策域、目标方向、逐条约束和容差；预测—决策链必须说明预测不确定性如何进入目标或约束。

### 5.4 求解策略

先给可验证基线，再说明结构降维、主算法、参数、初值/种子、终止条件和复杂度。启发式算法必须写“近似搜索”，除非存在全局证明或可核验 gap。

### 5.5 结果与解释

先报告题目直接要求的结果，再给物理/业务解释。结果同时提供未取整原值和按题意展示值；数值带单位、有效数字、适用情景和不确定性。不得只写“见附件”。

### 5.6 分问题检验

紧随本问结果放置最相关的验证，不把所有检验堆到文末。至少包含一项主求解内部检查和一项独立检查；报告指标、阈值、结果和是否通过，而不只展示图。

### 5.7 跨问交接

用一小段列出本问输出到下一问的变量、文件和口径。若后一问放宽可行域，保存本问方案作为下一问的初始可行解与支配基线。

## 6. 摘要数值契约

摘要最后撰写，按问题顺序组织。每一问用“任务—模型/算法—量化结果—验证/边界”四元句式；允许两句完成，不允许只列方法名。

每一问至少包含一个真正回答题目的结果数值，并同时给出：

- 指标名或物理量名，而非孤立数字。
- 单位、比例或无量纲口径。
- 适用情景/约束条件。
- 必要时给误差、置信区间、最优性 gap、最大约束违反量或相对基线提升。

年份、题号、样本量、随机种子、迭代次数和模型超参数不能替代结果数值。`0.95` 必须说明是置信水平、R²、准确率还是约束满足率。没有外推验证时不得写“预测准确”；没有界或证明时不得写“全局最优”；只有可行性复算时应写“近似可行方案”。

摘要数字的允许状态：

- `verified`：可直接陈述，并附验证口径。
- `provisional`：必须用“当前计算所得”“在所设情景下”或“启发式搜索得到”降级表述。
- `failed`：禁止进入摘要和结论。

若某问的交付是分类、规则或方案而非连续数值，仍应报告至少一个能衡量结果的数量，如正确率/效应量、覆盖率、成本、阈值、方案规模、约束满足率或相对基线变化；禁止用无关数字凑数。

摘要生成后执行反向核验：逐个提取数字，核对结果表字段、`run_id`、正文位置、验证状态和四舍五入误差。任一数字无法追溯则摘要审计失败。

## 7. 分问题验证契约

### 7.1 通用最低配置

每一问均须回答：结果是否正确、在何种范围有效、对扰动是否稳定、是否满足全部约束。至少保留：

1. 单位、数量级、边界/极限和公式—文字—表格一致性检查。
2. 基线或解析特例对照。
3. 一项独立实现、第二算法、小规模精确解、上下界或留出数据验证。
4. 关键参数/数据扰动及失效边界。
5. 取整后逐行复算最终交付结果。

### 7.2 按题型追加验证

| 题型 | 本问必须追加的验证 | 禁止的替代品 |
|---|---|---|
| 机理/PDE/ODE | 至少三档步长或网格；稳定性/守恒/参考解；参数区间与留出段 | “步长很小”、仅报训练 R² |
| 几何/轨迹/碰撞 | 等比例真实实体；连续事件括根与残差；退化情形；全量或无漏检审计 | 中心点或无限直线代理、仅看动画 |
| 确定性优化 | 可行基线；最大违反量；多初值；界/gap 或小规模精确对照 | 单次求解器成功状态 |
| 随机/启发式优化 | 固定种子集；至少 5 个有效独立种子，计算允许时建议 10–30 个；每种子收敛轨迹；最好/中位/最坏、离散度；最终方案确定性复算 | 只展示最好一次、只有均值无分布 |
| 多目标优化 | 可行 Pareto 前沿；代表解选择依据；权重/偏好扰动；支配关系检查 | 单一加权和且不解释权重 |
| 统计推断 | H0/H1、统计量、p 值、效应量、区间、诊断、多重比较处理 | 只报 `p<0.05` |
| 预测/校准 | 按组或时间外推切分；训练内预处理；朴素/季节基线；滚动指标和区间；泄漏检查 | 随机打乱时序、插值内评价 |
| 调度/离散事件 | 状态不变量、资源冲突、手算/小规模精确解、理论界、日志—甘特图一致 | 只给一张甘特图 |
| 随机仿真 | 预热/稳态规则、重复次数、种子、置信区间、分位数、最坏情景 | 单次随机轨迹 |

“至少 5 个种子”是最低审计门，不是统计充分性的保证。若解分布重尾、失败率高或种子间差异仍大，应继续增加重复次数并报告停止依据。

### 7.3 跨问验证

若后一问的可行域包含前一问：最大化问题的新结果不得低于旧可行方案，最小化问题的新结果不得高于旧可行方案。必须把旧方案注入新模型并重算，而不是只比较两张表。违反支配关系时，本问为 `fail`，直至解释口径变化或修复实现。

## 8. 图谱矩阵与自适应最低数量

图按“证据义务”配置，不按审美或固定张数配置。设子问数为 `Q`，正式图组的通用最低数为 `Q + 2`：一幅模型链/总体流程图、每问至少一幅核心证据图、一幅跨问鲁棒性或总体验证图。多面板计作一个正式图组，但每个面板必须可读、有独立编号和图注。

`Q + 2` 只是下限。下表中任一必备证据面板未被上述图组清晰承载时，必须追加图组：

| 活跃主张 | 必备证据面板 | 强制元素 |
|---|---|---|
| 数据质量/统计关系 | 缺失与分布；关系与不确定性 | 样本量、单位、异常处理、效应量/区间 |
| 机理拟合 | 实测—模拟；残差；网格/步长收敛 | 留出区间、误差指标、至少三档精化 |
| 预测/校准 | 训练—验证—未来分段；滚动误差/区间 | 基线、切分点、预测区间、外推指标 |
| 确定性优化 | 基线/候选对照；约束裕度；收敛或界 | 目标单位、可行边界、停止原因、gap（若有） |
| 随机/启发式优化 | 多种子收敛图；终值/可行率分布 | 各种子轨迹或中位带、最好/中位/最坏、种子数、失败率 |
| 多目标优化 | Pareto 前沿；代表解局部图 | 可行点、目标单位、膝点/偏好依据 |
| 连续几何事件 | 等比例实体图；事件函数局部图 | 真实边界、安全裕度、根区间、残差 |
| 调度/仿真 | 甘特图/时间线；利用率/等待/产出分布 | 事件编号、冲突检查、置信区间 |
| 鲁棒性 | 参数响应、龙卷风或情景箱线图 | 扰动范围、基准、失效阈值 |

随机优化必须同时出现“收敛”和“多种子分布”两类证据；单条最好轨迹不能满足要求。二者可排成同一正式图的两个面板，但不得省略种子数、离散度、失败运行和可行率。

图可以合并，证据不能合并消失。若一幅四面板图缩小后轴、图例或注释不可读，应拆图。正式图均需：中文字体可用、色盲友好、灰度可辨、轴和单位完整、图例不遮挡、关键阈值/基线可见；几何图等比例；位图通常至少 300 dpi，并保留 PDF/SVG。所有绘图数字直接读取结果表，不手工输入。

禁止图：软件默认截图、三维饼图、装饰性流程图、没有单位的曲线、用平滑线掩盖原始数据、只展示训练拟合、只展示随机算法最好一次、无法对应正文主张的图。

## 9. 表格、结果与数值一致性

每张结果表保留三层值：计算原值、论文展示值、取整后复算值。表头必须写单位；同列精度一致；缺失、不可用和零值不能混用。

最终结果表必须能触发自动复算：

- 重新计算全部约束、派生指标、比例和总量。
- 报告最大约束违反量、最小安全裕度、可行率和边界约束。
- 检查同一变量在摘要、正文、表、图、附件中的一致性。
- 检查公式定义与表中计算口径一致，例如偏差率不能写成完成率。
- 检查后一问放宽可行域时的支配关系。

论文不得从控制台、截图或旧文档手工抄数。数值变化后应由脚本重建表、图和摘要候选清单。

## 10. 参考文献与正文引用契约

### 10.1 必须引用的内容

- 非题面给出的事实、数据、参数、标准和行业背景。
- 核心模型、定理、算法、统计检验和评价指标的来源。
- 用于对比本文结果的外部数值或结论。
- 直接改写或继承的图、表、公式和代码思想。

题面直接事实应标注“题面/附件”，不伪装成外部研究；自行推导的公式不应虚构引文，但应给出推导。

### 10.2 来源优先级

优先使用官方题面与标准、原始论文、权威教材、同行评议论文和权威机构数据。网页适合支持发布日期明确的官方信息或背景，不应作为核心机理和算法唯一依据。二手教程只能作为检索线索，关键结论回溯到一手来源。

### 10.3 引用落点与核验

引用紧跟被支持的句子、公式或参数，不在段末堆一串无法对应的编号。每条参考文献核验作者、题名、期刊/出版社、年份、卷期页、DOI/URL 和访问日期；DOI 必须可解析，URL 应指向具体页面。

生成“引用—主张表”，逐条检查：

- 引文是否真的支持对应主张，而非只主题相近。
- 正文每个编号是否存在于文末，文末每条是否在正文被引用。
- 同一来源是否被重复建条目。
- 是否存在作者、年份、题名、DOI 拼接或 AI 生成的虚假文献。
- 引用数量是否由实际需要决定，而非为显得专业而堆砌。

若赛题或当年规范要求特定格式，以当年规范为准。无法访问全文时不得声称已核对其中细节；可降级为“元数据已核验，正文未核验”。

## 11. Pass / Conditional / Fail 审计

每一问和整篇论文分别审计。状态只允许 `pass`、`conditional`、`fail`，并记录证据路径和责任模块。

### 11.1 Pass

仅当以下条件全部满足：

- 题目交付覆盖完整，四类写前工件完成。
- 摘要数字全部可追溯且状态为 `verified`，或已准确标注近似/有界性质。
- 单位、数据切分、数值收敛、统计逻辑、随机重复、可行性和跨问支配等所有适用硬门通过。
- 每个核心结论至少有一项独立验证。
- 图谱达到自适应最低配置，随机优化含收敛与多种子分布。
- 引用无虚构、无断链；最终 PDF 版式和文件完整性检查通过。

`pass` 只表示通过内部交付标准，不表示或保证获奖。

### 11.2 Conditional

允许存在不影响主要答案的已披露限制，例如：次要敏感性样本不足、外部资料正文无法获取、非核心扩展实验未完成、某项结论只能标记 `provisional`。必须同时满足：

- 没有核心交付缺失和硬门失败。
- 不确定内容不进入摘要强结论，并在正文写明影响范围。
- 给出解除条件、待补实验和负责人/脚本位置。

`conditional` 可以生成带显著警告的审阅稿，不能标记为最终高水平交付稿。

### 11.3 Fail

出现任一项即失败：

- 题面要求、必填表或关键附件缺失。
- 摘要数字不可追溯、来自不同运行或与正文矛盾。
- 量纲/时间尺度错误、数据泄漏、H0/H1 逻辑反写。
- 数值未收敛却宣称精确，启发式无界却宣称全局最优。
- 最终方案违反约束、取整后不可行、嵌套可行域支配关系被破坏。
- 随机算法只有单次运行，或隐藏失败种子。
- 核心结论没有独立验证。
- 引用虚构、错配或无法支持关键主张。
- 图表篡改、手工抄数、图表与结果表不属于同一运行。

失败时保留已验证产物，回到对应模型、求解或数据阶段修复；禁止用文字润色绕过失败。

## 12. 终稿发布清单

发布前逐项确认：

- [ ] 题面、附件、输入、环境、代码和最终 PDF 哈希已写入清单。
- [ ] 四类写前工件齐全，逐问交付矩阵无空项。
- [ ] 每问均按任务—模型—求解—结果—检验—交接闭环。
- [ ] 摘要每问有结果数值、指标/单位、条件和验证边界。
- [ ] 所有摘要数字、表格和图来自同一 `run_id`。
- [ ] 所有适用的分问题验证与跨问支配检查完成。
- [ ] 随机优化保存种子、完整收敛轨迹和多种子分布。
- [ ] 最终方案逐行复算，取整后仍可行。
- [ ] 图谱数量达到 `Q + 2` 通用下限并覆盖全部活跃证据义务。
- [ ] 图、表、公式、符号、单位、有效数字和题号全文一致。
- [ ] 每条关键外部主张有准确引用，引用—主张表通过。
- [ ] 局限、适用域、失效边界和近似标签真实披露。
- [ ] 正文紧凑，通常落在建议篇幅内，无灌水和装饰性产物。
- [ ] AI 使用说明、代码和支撑材料符合当年竞赛规则。
- [ ] PDF 逐页视觉检查通过，字体嵌入、图片清晰、表格不越界、链接/目录有效。
- [ ] 整篇和各问审计均为 `pass`；若为 `conditional`，明确阻止最终发布。

最终交付说明必须包含一句边界声明：本论文包通过内部可复现与证据审计，不构成对竞赛奖项、名次或评审结果的保证。

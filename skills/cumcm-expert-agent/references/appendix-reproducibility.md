## 一、PDF 展示与电子材料

把“便于评阅的 PDF 摘要”和“可执行的电子交付包”分开。完整求解代码、递归本地依赖、测试、输入模板、结果文件、验证生成器、图表/截图生成器和依赖锁必须进入电子包；PDF 附录不用铺满全部源码，只展示：

1. 重建与核验入口、完整电子文件清单、正式环境和预先声明的复现容差；
2. 1--3 组决定性代码片段，优先选择模型判据、核心算法和约束复核；
3. 官方结果表的必填区域或关键中间数据截图；
4. 主结果、多初值离散、约束违反、结果表反算误差及结论边界；
5. `reproducible`、`frozen` 和 `stale` 产物的明确区分。

## 二、机器可读复现清单

在电子包中生成 `reproducibility/manifest.json`，不得用正文表格或未展开的 glob 代替。至少记录：

- `schema_version`、正式运行编号、入口命令和仓库相对根目录；
- `delivery_files`：除清单自身、审计报告和最终校验侧车外，每个实际交付文件的相对路径、用途和 SHA-256；不得在清单内部记录清单自身哈希而形成循环；
- `formal_environment`、依赖锁相对路径及锁文件 SHA-256；
- `input_bundle_sha256`：原始输入、递归源码、配置、依赖锁和生成器的联合指纹；
- `tolerances`：各类数值/结构/像素比较的预设规则；
- `coverage_map`：题目必填字段和关键主张到源单元格、截图及附录位置的映射；
- `artifacts`：每个 JSON、XLSX、图、截图、表、PDF 和验证报告的生产记录。

每条 `artifacts` 记录至少包含：

```json
{
  "id": "appendix-result3",
  "path": "figures/appendix-result3.png",
  "kind": "screenshot",
  "status": "reproducible",
  "producer": {
    "command": "python scripts/render_appendix.py --asset appendix-result3",
    "files": [{"path": "scripts/render_appendix.py", "sha256": "..."}]
  },
  "inputs": [{"path": "outputs/result3.xlsx", "sha256": "..."}],
  "source_locator": {"sheet": "Sheet1", "range": "A1:L16"},
  "source_payload_sha256": "...",
  "output_sha256": "...",
  "rerender_sha256": "...",
  "comparison": {"mode": "pixel", "pixel_sha256": "..."},
  "coverage_ids": ["result3.required-fields"]
}
```

`producer.command`、生产者文件和输入必须真实存在。任何字段冲突、缺失文件、哈希不符或未展开路径都判为失败，不得手工选择一个“看起来正确”的版本继续交付。

## 三、截图生成、重渲染与覆盖映射

把可复现截图限定为**由已交付生成器直接读取正式源文件后确定性生成的资产**。手工截图、手工重排数字、从论文反抄数据、伪造 IDE/Excel 界面或生成后修图均不得标记为可复现。

生成器必须：

1. 逐行或逐单元格读取清单指定的源范围，独立导出规范化文本/单元格载荷并计算 `source_payload_sha256`；不得在绘图代码中硬编码结果数字；
2. 只在内存或临时副本中调整显示精度，不得保存覆盖已哈希绑定的正式源码或 XLSX；
3. 在空临时目录删除旧资产后重渲染，记录 `output_sha256`；PNG 等位图还要对解码后的像素计算 `pixel_sha256`，PDF/SVG 则渲染到固定尺寸像素后比较页面哈希；
4. 要求首次生成与重渲染哈希一致。若格式包含不可控时间戳，先规范化元数据，再比较规范化文件哈希和像素哈希；不能稳定重渲染则标记 `frozen`，不得伪称确定性截图；
5. 在图注中写相对路径、行号或工作表范围、源文件哈希前缀、显示精度和产物状态，不暴露绝对路径、用户名、密钥或编辑器会话。

独立审计步骤必须重新抽取源范围并核对 `source_payload_sha256`，不能只相信生成器自报。代码截图逐行比对源文本；表格截图逐单元格比对值、类型和单位。

建立 `coverage_map`，至少覆盖官方结果模板的全部必填行列、摘要/结论中的关键数字及约束/误差证据。每个必填字段必须映射到源单元格和至少一个可读附录位置；缺行、缺列、裁掉失败记录或只展示最好样本均判为失败。工作表图注还要说明“单行时长之和”与“区间并集”是否一致，避免重复计分。

## 四、完整代码闭包与干净目录重建

把“完整代码”定义为所有重建入口的递归本地依赖闭包，包括数据预处理、模型求解、模板写入、验证生成、图表/截图生成、论文构建、审计脚本及实际运行的测试；第三方库用锁文件声明，不复制库源码。清单不得只列主脚本而遗漏被 import、include、调用或读取的本地文件。

交付前必须：

1. 将 `delivery_files` 中的文件复制或解压到新的空目录，拒绝越出交付根目录的符号链接和本地绝对路径；
2. 从声明的依赖锁建立干净环境，随后禁止依赖未声明的私有服务、原工作区文件或隐式网络素材；
3. 删除所有声明为可重生的派生产物，按 DAG 拓扑顺序执行 `rebuild` 命令，再执行测试和 `verify` 命令；
4. 记录每条命令、工作目录、环境指纹、退出码、标准输出摘要、开始/结束时间和生成文件哈希；
5. 对比重建产物与正式产物，按预先声明的 `byte`、`pixel`、`numeric` 或 `structural` 规则判定。

明确区分命令语义：`verify` 可以读取已有结果，只证明现有产物内部一致；`rebuild` 必须从声明的原始输入重新生成目标，不能读取目标文件或其下游产物。只运行快速核验不得写成“一键重建”。

## 五、产物 DAG 与冻结证据

在 `manifest.json` 中把每个产物登记为 DAG 节点，列出生产者、直接输入、输出和状态。拒绝环、缺生产者、生产者在交付包外以及“目标产物同时作为自身生产输入”的记录。

状态只允许：

- `reproducible`：生产者和全部输入已交付，并通过干净目录重建与比较；
- `frozen`：历史/外部产物、生产者缺失、依赖不可获得或无法稳定重建；必须记录原因、来源、最后环境、可支持和不可支持的主张；
- `stale`：任一上游指纹已变化但尚未重建；禁止进入最终论文或交付结论。

`frozen` 产物可以作为有来源说明的背景交叉检查，但不得计入当前一键重建、不得单独满足独立验证/鲁棒性硬门禁，也不得支撑只有当前计算才能证明的主张。若附录展示冻结产物，必须在文件清单、图注和主张—证据映射中同时标明 `FROZEN`。

## 六、正式环境、容差与变更失效

从**实际生成正式产物的进程**捕获环境，不从论文或旧 JSON 反抄。至少记录：Python `-VV`、完整传递依赖锁、NumPy/SciPy/BLAS 与求解器版本、OS/架构、线程数和确定性开关、随机种子；使用 MATLAB 时记录 release、工具箱和外部求解器；重建论文时记录 TeX 引擎、关键包和字体。将环境清单与锁文件哈希写入产物记录。

从锁文件创建干净环境并运行重建。当前环境、锁文件、正式运行日志或验证 JSON 任意不一致时立即失败：选择一致环境重算，或把旧产物标记 `frozen`；不得只修改文字或锁文件来追平旧记录。

在运行前为每类产物声明比较方式：确定性文本/代码优先 `byte`；截图优先规范化文件哈希加 `pixel`；数值 JSON/XLSX 使用字段级 `numeric`/`structural`，明确 `atol`、`rtol`、单位、必需字段和约束不变量。不得看过差异后放宽容差。若允许元数据差异，必须列出可忽略字段，不能笼统写“结果基本一致”。

用原始输入、递归源码、配置、依赖锁、生成器和容差规则计算 `input_bundle_sha256`。任一上游变化都必须沿 DAG 把截图、验证、表格、论文 PDF 和旧 QA 标为 `stale`；完成重建、重渲染、论文编译和逐页视觉复核后才能恢复 `reproducible`。

## 七、版面与发布硬门禁

- 参考文献在前，附录另起页，避免文献与代码/数据图混排。
- 代码字号在最终 PDF 中不小于 7 pt，表头、单位和数字不小于 8 pt；必要时使用横向页。
- 截图使用白底、高对比文字和少量语义色；不保留 IDE 菜单、深色主题、桌面背景或无关窗口。
- 代表性代码图注必须指向完整电子文件，不得用 1--3 张截图暗示已经展示全部代码。

交付前执行随电子包交付的确定性复现审计器，生成 `reproducibility/audit-report.json`。只有以下检查全部为 `PASS` 才能标记“可复现交付”：

- 清单格式、文件存在性、逐文件哈希和依赖闭包；
- DAG 无环、生产者/输入完整、`reproducible`/`frozen`/`stale` 分类合法；
- 干净目录重建、测试和正式命令全部成功；
- 截图源载荷、覆盖映射、重渲染文件/像素哈希全部一致；
- 正式环境与依赖锁一致，比较容差在运行前声明且全部通过；
- 没有 `stale` 产物进入 PDF，没有 `frozen` 产物被计入当前复现或验证门禁；
- 附录摘要、正文、结果表和机器清单中的关键数字一致。

审计器脚本进入 `delivery_files`。审计报告记录清单 SHA-256 和审计器 SHA-256；审计完成后再生成 `reproducibility/bundle.sha256`，逐文件绑定最终电子包中的清单、审计报告、审计器及全部交付文件，但不记录校验侧车自身。这样形成“清单 → 审计报告 → 最终侧车”的单向绑定，禁止自哈希循环。手工编写 `PASS` JSON、只运行现有产物核验或用最终答复解释失败均不构成通过。

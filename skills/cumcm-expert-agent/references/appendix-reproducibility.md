# 附录与复现证据标准

复现能力由“源文件—输入—命令—环境—校验”链条证明，不由截图数量证明。截图不是附录标配；没有任何截图可以是完全合格、而且通常更好的交付。

## 一、PDF 附录与电子交付包

把“便于评阅的 PDF 附录”和“可执行的电子交付包”分开：

- 电子包包含完整求解代码及递归本地依赖、原始输入、配置、测试、依赖锁、结果文件、验证/图表生成器、机器清单和重建入口。只有通过第二节必要性测试的截图才需要截图生成器。
- PDF 附录只保留重建入口、环境与容差摘要、完整电子文件索引、关键模型/算法代码摘录、紧凑结果表、约束/误差摘要以及 `reproducible`、`frozen`、`stale` 状态说明。
- 代码摘录使用 LaTeX/Word 代码清单或由源文件自动抽取的可选择文本，标注相对路径与行号；源代码截图不能代替代码清单或电子源码。
- 数值使用排版表格或从 CSV/JSON/XLSX 直接生成的表格；结果表截图不能代替机器可读结果与单元格级校验。
- 运行日志以文本、JSON 或紧凑摘要交付；终端、IDE、文件浏览器和测试面板截图不构成更强的运行证据。

附录篇幅和图片数量没有最低配额。某类证据已经在正文表格、公式或电子清单中完整出现时，不得为了“显得可复现”再做一页视觉副本。

## 二、附录截图必要性测试

每个拟进入 PDF 的截图先登记 `screenshot_decision`：

```yaml
screenshot_decision:
  id: official-template-layout
  claim: 官方结果模板的必填区域已按规定布局写入
  source: outputs/result.xlsx
  source_locator: Sheet1!A1:L16
  alternatives_checked: [generated_table, cell_manifest, selectable_text]
  visible_state_required: true
  information_lost_without_screenshot: 合并单元格、表头层级与填入位置
  unique_evidence: 相对单元格清单新增官方模板视觉位置证据
  decision: screenshot          # screenshot | omit
```

只有以下各项全部为真，`decision` 才能为 `screenshot`：

1. 主张依赖可见的界面、版式、交互状态或渲染状态；仅依赖代码文本、数值、日志或文件是否存在时不通过。
2. 可选择文本、生成表格、CSV/JSON、相对路径 + 行号/单元格定位和内容哈希不能以同等或更高精度保留该证据。
3. 截图相对已有正文、表格、图和其他截图增加独立证据，不是同一内容的“证据墙”副本。
4. 截图能从已交付源文件和已交付生成器重生，或被诚实标记为 `frozen`；不得手工重排数字、从论文反抄数据或伪造 IDE/Excel 界面。
5. 截图不会成为代码、数据或测试结果的唯一可读载体，并且不会暴露用户名、绝对路径、密钥、令牌或无关桌面状态。

下列候选默认判为 `omit`：

- 源代码、配置文件和命令行：改用代码清单、文本文件与命令记录。
- 结果数值、长表和工作簿单元格：改用生成表格、机器文件、源定位与字段级校验。
- 测试通过、运行日志、环境版本和文件哈希：改用 JSON/文本审计报告。
- 已经作为正文正式图导出的图像：它是图，不是“截图证据”，不得再套一层卡片或浏览器外框。

官方填报模板的视觉位置、必须保留的 UI 参数状态、交互式工具不可导出的状态或排版/渲染缺陷可以条件性通过。通过后仍须：

- 裁到主张所需的最小范围；除非 UI 本身是证据，否则去掉菜单、标题栏、卡片头、状态条、桌面背景和无关留白。
- 每个不同视觉状态最多保留一个代表性截图；不得把多张截图拼成整页“验证海报”。
- 图注写明必要性、相对源路径、源定位、生成命令、源载荷哈希前缀和产物状态。
- 首次生成与空临时目录重生成均由同一生成器读取正式源文件。比较方式按第六节选择，不能默认要求像素完全相同。

`screenshot_decisions: []` 是合法且可通过审计的结果。审计器在没有截图时应把截图专属检查标为 `NOT_APPLICABLE`，不能为了凑齐检查项反向制造截图。

## 三、机器可读清单与覆盖映射

在电子包中生成 `reproducibility/manifest.json`，不得用正文表格、截图或未展开的 glob 代替。至少记录：

- `schema_version`、正式运行编号、仓库相对根目录、`rebuild` 与 `verify` 入口命令；
- `delivery_files`：除清单自身、审计报告和最终校验侧车外，每个实际交付文件的相对路径、用途和 SHA-256；
- `formal_environment`、依赖锁相对路径及其 SHA-256；
- `input_bundle_sha256`：原始输入、递归源码、配置、依赖锁、生成器和比较规则的联合指纹；
- `tolerances`：各类数值、结构、文本或必要截图比较的预设规则；
- `coverage_map`：题目必填字段和关键主张到源文件/单元格、正文或附录位置和验证项的映射；截图字段必须可空；
- `screenshot_decisions`：包含全部实际入选截图的必要性记录；无截图时为空数组；
- `artifacts`：每个结果、表、图、论文、验证报告和必要截图的生产记录。

普通结果产物优先采用下列记录方式：

```json
{
  "id": "result3-table",
  "path": "outputs/result3.xlsx",
  "kind": "workbook",
  "status": "reproducible",
  "producer": {
    "command": "python scripts/build_results.py --question 3",
    "files": [{"path": "scripts/build_results.py", "sha256": "..."}]
  },
  "inputs": [{"path": "results/q3.json", "sha256": "..."}],
  "source_locator": {"sheet": "Sheet1", "range": "A1:L16"},
  "source_payload_sha256": "...",
  "output_sha256": "...",
  "comparison": {"mode": "numeric_structural", "atol": 1e-9, "rtol": 1e-9},
  "coverage_ids": ["result3.required-fields"]
}
```

若产物确为必要截图，额外记录 `screenshot_decision_id`、生成尺寸、字体/渲染器环境和对应比较规则。`producer.command`、生产者文件、输入和定位必须真实存在；字段冲突、缺失文件、哈希不符或未展开路径均判为失败。

`coverage_map` 的目标是把必填字段和关键主张绑定到源值与可读位置，不是强制把每个值绑定到一张截图。每个官方必填字段至少映射到源单元格、机器验证项及正文/附录表格位置；只有截图必要性测试通过时才增加截图映射。缺行、缺列、裁掉失败记录或只展示最好样本均判为失败。

## 四、完整代码闭包与干净目录重建

把“完整代码”定义为所有重建入口的递归本地依赖闭包，包括数据预处理、模型求解、模板写入、验证生成、正式图生成、论文构建、审计脚本及实际运行的测试；第三方库用锁文件声明，不复制库源码。清单不得只列主脚本而遗漏被 import、include、调用或读取的本地文件。

交付前必须：

1. 将 `delivery_files` 中的文件复制或解压到新的空目录，拒绝越出交付根目录的符号链接和本地绝对路径；
2. 从声明的依赖锁建立干净环境，随后禁止依赖未声明的私有服务、原工作区文件或隐式网络素材；
3. 删除所有声明为可重生的派生产物，按 DAG 拓扑顺序执行 `rebuild`，再执行测试与 `verify`；
4. 记录每条命令、工作目录、环境指纹、退出码、标准输出摘要、开始/结束时间和生成文件哈希；
5. 按预先声明的 `byte`、`text`、`numeric`、`structural`、`visual` 或条件性 `pixel` 规则比较重建产物与正式产物。

`verify` 可以读取已有结果，只证明现有产物内部一致；`rebuild` 必须从声明的原始输入重新生成目标，不能读取目标文件或其下游产物。只运行快速核验不得写成“一键重建”。

## 五、产物 DAG 与状态

在 `manifest.json` 中把每个产物登记为 DAG 节点，列出生产者、直接输入、输出和状态。拒绝环、缺生产者、生产者在交付包外以及“目标产物同时作为自身生产输入”的记录。

状态只允许：

- `reproducible`：生产者和全部输入已交付，并通过干净目录重建与预设比较；
- `frozen`：历史/外部产物、生产者缺失、依赖不可获得或无法合理重建；必须记录原因、来源、最后环境、可支持和不可支持的主张；
- `stale`：任一上游指纹已变化但尚未重建；禁止进入最终论文或交付结论。

`frozen` 产物可以作为有来源说明的背景交叉检查，但不得计入当前一键重建，不得单独满足独立验证/鲁棒性门禁，也不得支撑只有当前计算才能证明的主张。若附录展示冻结产物，必须在文件清单、图注或表注和主张—证据映射中同时标明 `FROZEN`。

## 六、环境、比较方式与变更失效

从实际生成正式产物的进程捕获环境。至少记录 Python `-VV`、传递依赖锁、NumPy/SciPy/BLAS 与求解器版本、OS/架构、线程数、确定性开关和随机种子；MATLAB 记录 release、工具箱和外部求解器；论文记录 TeX 引擎、关键包与字体。环境清单和锁文件哈希进入产物记录。

比较方式必须在运行前按主张选择：

- 源代码、配置和确定性文本优先 `byte` 或规范化 `text`；
- JSON、CSV 和 XLSX 优先字段级 `structural`/`numeric`，明确必需字段、单位、`atol`、`rtol` 与约束不变量；
- 正式图和论文 PDF 以源数据绑定、结构检查、最终尺寸检查和逐页视觉复核为主；文件字节因元数据不同不等于科学内容失败；
- 必要截图只有在主张本身依赖逐像素渲染、且字体、渲染器、系统缩放和尺寸均锁定时才使用 `pixel`。若主张只是表格值、文本或控件状态，则用载荷、OCR/文本、结构或区域级比较，不能把无关的抗锯齿差异升级为复现失败。

不得看过差异后放宽容差。若允许元数据差异，必须列出可忽略字段。不要因为无关像素无法稳定就把本可结构验证的产物标成 `frozen`；应先改用与主张匹配的比较方式。

任一原始输入、递归源码、配置、依赖锁、生成器或比较规则变化，都必须沿 DAG 把相关结果、图、必要截图、验证、论文 PDF 和旧 QA 标为 `stale`；完成重建、论文编译和逐页视觉复核后才能恢复 `reproducible`。

## 七、人工论文风格检查

附录完成后必须检查实际 PDF，而不是只看单个导出资产。记录 `human_appendix_style_review`，至少包含评阅者、PDF SHA-256、检查时间、以下逐项结论与修订记录：

1. 附录使用普通论文的章节、段落、代码清单、表格和图注层级，不像产品演示、网页仪表盘或拼贴海报。
2. 代码是可选择文本，数据是排版表格；截图不是源码、数值或测试状态的唯一证据。
3. 每张截图都能对应一个已通过的 `screenshot_decision`，且只保留主张所需区域；没有彩色卡片头、证据 A/B 徽章、IDE 外框或装饰性留白。
4. 除官方填报模板或主张本身要求的完整视觉状态外，没有整页位图。不得仅为容纳截图而旋转整页或使用横向大海报版式。
5. 最终 PDF 中代码不小于 7 pt，表头、单位和数字不小于 8 pt；宽表优先拆表、重复表头或单独横向排版，而不是缩成不可读截图。
6. 参考文献在前、附录另起页；正文、附录摘要、结果表和机器清单中的关键数字一致，且无绝对路径、用户名、密钥或会话信息。

任一项为 `FAIL` 时不得发布。自动截图哈希、OCR 或版式 lint 通过不能覆盖人工风格否决。

## 八、发布硬门禁

交付前执行随电子包交付的复现审计器，生成 `reproducibility/audit-report.json`。只有以下检查全部为 `PASS`（无截图时截图专属项为 `NOT_APPLICABLE`）才能标记“可复现交付”：

- 清单格式、文件存在性、逐文件哈希和递归依赖闭包完整；
- DAG 无环，生产者/输入完整，`reproducible`/`frozen`/`stale` 分类合法；
- 干净目录重建、测试和正式命令全部成功，`rebuild` 与 `verify` 语义没有混用；
- `coverage_map` 把关键主张与必填字段绑定到源值、机器验证和可读论文位置，不要求无意义截图；
- 每张实际入选截图均通过必要性测试、源载荷核验与预设重生成比较；不存在截图时不得因此失败；
- 源代码、结果数值、日志和测试状态均有文本或机器可读证据，没有由截图单独支撑；
- 正式环境与依赖锁一致，比较容差在运行前声明且全部通过；
- 没有 `stale` 产物进入 PDF，没有 `frozen` 产物被计入当前复现或验证门禁；
- `human_appendix_style_review` 全项通过，附录没有截图墙、卡片化证据海报或不可读整页位图；
- 附录摘要、正文、结果表和机器清单中的关键数字一致。

审计器脚本进入 `delivery_files`。审计报告记录清单 SHA-256 和审计器 SHA-256；审计完成后再生成 `reproducibility/bundle.sha256`，逐文件绑定最终电子包中的清单、审计报告、审计器及全部交付文件，但不记录校验侧车自身。这样形成“清单 → 审计报告 → 最终侧车”的单向绑定，禁止自哈希循环。手工编写 `PASS` JSON、只运行现有产物核验或用最终答复解释失败均不构成通过。
